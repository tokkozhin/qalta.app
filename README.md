# Qalta - AI Expense Tracker

Website for [qalta.app](https://qalta.app), served by a Cloudflare Worker.

## Languages

Pages are generated from `site/templates/` and the dictionaries in `site/i18n/<lang>/`. English is served at the root, other languages under `/<lang>/`. The Worker in `src/index.ts` redirects unprefixed pages to the visitor's language (the `lang` cookie set by the footer switcher, then `Accept-Language`), falling back to English.

Do not edit the generated HTML in `public/` by hand. Edit the English strings in `site/i18n/en/`, update the other languages, then:

```sh
npm run check:i18n   # every language has the same keys, tags, and links as English
npm run build        # writes public/**/*.html and public/sitemap.xml
npm run dev          # build and serve locally
npm run deploy       # build and deploy
```

Deployment uses `wrangler.jsonc` for the existing `qalta-app` Worker and `qalta.app` custom domain. Run `npm run deploy:check` and `npm run test:consent` before `npm run deploy`. OAuth consent is served at `/oauth/consent/` without language redirects.

## MCP proxy and support

The same Worker serves `https://mcp.qalta.app/mcp` and proxies only that endpoint to the existing Supabase MCP function. OAuth protected-resource discovery advertises the public MCP URL; the authorization server and issuer stay on Supabase. The proxy preserves bearer tokens and streaming MCP responses, does not follow upstream redirects, and does not cache responses. The website's language redirects do not apply to the MCP host.

`/support` is generated by `site/templates/support.mjs`, in Russian for `/ru/support` and English for the other site languages. Footer support links lead to this page. Update support content in the template, not generated HTML.

Before deploying, run `npm run test:mcp`, `npm run test:consent`, `npm run check:i18n`, and `npm run deploy:check`. Deployment attaches the `mcp.qalta.app` custom domain to the existing Worker; no Supabase custom-domain add-on is needed.

For OpenAI verification, set `vars.OPENAI_APPS_CHALLENGE` in `wrangler.jsonc` to the exact token provided by the submission portal, regenerate types with `npx wrangler types`, and redeploy. The token is public verification content, not an API credential. Until it is configured, `/.well-known/openai-apps-challenge` returns 404. Once configured, that path serves plain text on both `qalta.app` and `mcp.qalta.app`, without language redirects. Do not change the Supabase OAuth issuer to the proxy domain.

After deployment, check unauthenticated `/mcp` returns 401 with a public `resource_metadata` URL, discovery returns `resource: https://mcp.qalta.app/mcp`, and `/support` returns 200. Complete an OAuth connection in the target assistant and a read-only tool call using a test account before submitting to a directory; unauthenticated checks cannot verify the full sign-in flow.
